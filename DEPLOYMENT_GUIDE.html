How to Acquire & Set Up Your Domain on Hostinger

Since you have a Hostinger plan (supporting up to 50 websites), you have three simple options to get your domain ready. Pick the one that applies to you:

Option A: Claim the Free Domain Included in Your Hostinger Plan (Recommended)

Most Hostinger plans include 1 free domain registration for the first year (.com, .net, etc.):

  1. Log into your Hostinger hPanel ↗.
  2. Look at the top of your dashboard. If you haven't claimed it yet, you will see a banner: "Claim your free domain". Click Claim Domain.
  3. Enter your desired domain name (e.g., cryptofindertools.com, solarcforensics.com, or rh-sniper.com) and pick .com.
  4. Click Check Availability. If it's available, click Claim Domain.
  5. Fill in your basic registration contact details and click Finish Registration. Hostinger will automatically attach it to your hosting account!

Option B: Use an Existing Domain & Create a Subdomain (Zero Cost)

If you already have a domain active on Hostinger (e.g., mytradingbrand.com), you can create a free subdomain like tracker.mytradingbrand.com:

  1. In Hostinger hPanel, click Websites in the top menu → click Manage next to your website.
  2. In the left sidebar, navigate to:
    Domains → Subdomains
  3. In the "Create a Subdomain" box:
    • Enter: tracker
    • Leave the checkbox "Custom folder for subdomain" unchecked (it will auto-create public_html/tracker/ or create a new site).
  4. Click the purple Create button. You now have a clean, isolated frontend URL!

Option C: Purchase a New Cheap Domain ($0.99 – $9.99)

If you want a brand-new custom domain:

  1. In hPanel, click Domains in the top menu → click Get a new domain.
  2. Search for your domain (e.g., .xyz, .online, or .com).
  3. Complete the checkout. Hostinger will immediately activate it inside your hPanel.

How to Configure DNS in Hostinger for Vultr (Click-by-Click)

This step connects your domain to both servers: Hostinger serves the frontend website, while Vultr serves the background API. Here is exactly how to set up the DNS:

2.1 Locate Your Vultr VPS IPv4 Address

  1. Log into your Vultr Dashboard ↗.
  2. Click on Products → Compute → click on your Ubuntu VPS instance.
  3. Under the server details, copy the IP Address (e.g. 149.28.123.45). You will need this in the next step.

2.2 Open the DNS Zone Editor in Hostinger hPanel

  1. In Hostinger hPanel, click Domains in the top navigation bar.
  2. Click directly on your domain name (e.g., yourdomain.com).
  3. In the left sidebar menu, click:
    DNS / Nameservers
  4. Scroll down to the "Manage DNS records" box.

2.3 Add the "A" Record for the Vultr API

Fill in the fields exactly as shown in this table:

Field Value to Enter Explanation
Type A Select "A" from the dropdown.
Name api Just type api. Hostinger automatically appends your domain to make api.yourdomain.com.
Points to [YOUR_VULTR_IPV4] Paste your Vultr IP address (e.g. 149.28.123.45).
TTL 300 300 seconds (5 minutes). This ensures fast propagation.
  1. Click the purple Add Record button. Hostinger will show a green confirmation toast: "DNS record created successfully".

2.4 Verify DNS Propagation Worldwide

Before requesting free SSL on Vultr in Step 4, verify that the internet can see your new api address:

  1. Open DNSChecker.org ↗ in your browser.
  2. In the search box, enter: api.yourdomain.com.
  3. Leave the dropdown on A, and click Search.
  4. Once you see green checkmarks showing your Vultr IP address across the map (usually takes 2–10 minutes), your DNS is 100% ready!

How to Clear or Drain the Existing Local Work Queue

Inside forensics.db, there is an ingestion_jobs table. When our stream tests ran, 39 tokens were placed in the queue waiting for forensic enrichment. You have two choices:

Choice A: Drain the Queue Gracefully (Enrich the Tokens)

This command claims jobs from SQLite, fetches their contract creation and funder lineage, computes nearest duplicate scores, and saves them into the dashboard:

python streamer.py --drain --max-jobs 10

What you will see in the terminal:

2026-09-20T... INFO enriching 0xa249... on RBH from uniswap_v4_initialize (attempt 1)
Generated dashboard atomically in c:\...\Robinhood
Generated API snapshot atomically at c:\...\runtime\dashboard_candidates.json
{
  "claimed": 10,
  "failed": 0,
  "succeeded": 10
}

Check the remaining count with:

python streamer.py --status

Repeat python streamer.py --drain --max-jobs 10 until "pending": 0.

Choice B: Instant Reset (Wipe Pending Queue for Fresh Production Start)

If you want to clear the pending queue instantly without waiting for all tokens to enrich locally, run this 1-line command in PowerShell:

python -c "from database import ForensicDatabase; db = ForensicDatabase('forensics.db'); db.execute_write('DELETE FROM ingestion_jobs WHERE status=\"pending\"'); print('Pending queue reset successfully!')"
python streamer.py --status
✓
Why Choice B is completely safe: It only deletes un-enriched pending queue items. It does not delete any of your qualified anchor tokens, dev habits, fingerprints, or historical records! Output will immediately show "pending": 0.

Deploy The Vultr Backend Engine (Full Step-by-Step Commands)

4.1 Connect to Your Vultr Server via SSH

Open PowerShell (Windows) or Terminal (Mac/Linux) and run:

ssh root@YOUR_VULTR_IP

Type yes if prompted about host authenticity, then paste your Vultr root password (characters won't show on screen as you type—just press Enter).

4.2 Install System Packages & Clone the Repository

Copy and paste this entire block into your Vultr terminal:

sudo apt update && sudo apt install -y git python3 python3-venv nginx curl certbot python3-certbot-nginx
sudo git clone https://github.com/Jorence19/OmniReborn.git /opt/omnireborn
cd /opt/omnireborn
sudo bash deploy/install_vultr_backend.sh
ℹ️
What happens here: The installer sets up an isolated system user (omnireborn), creates Python virtual environment .venv, installs all requirements, copies the database, and creates /etc/omnireborn.env. It pauses so you can enter your keys.

4.3 Edit Your Production Environment File

Open the configuration file with the nano editor:

sudo nano /etc/omnireborn.env

Replace with your real RPC URLs and domain names:

ENABLED_CHAIN_IDS=4663,5042
ROBINHOOD_RPC_URL=https://YOUR_PRIVATE_ROBINHOOD_RPC
ARC_RPC_URL=https://YOUR_PRIVATE_ARC_RPC
ROBIN_ETHERSCAN_API_KEY=V3PFHFXJUWDH7AVUS26E9QUNTTTJ1QE5D4
API_ALLOWED_ORIGINS=https://tracker.yourdomain.com
API_ALLOWED_HOSTS=api.yourdomain.com,localhost,127.0.0.1
DASHBOARD_API_URL=https://api.yourdomain.com/api/candidates
💡
How to save in Nano: Press Ctrl + O → press Enter to confirm filename → press Ctrl + X to exit.

4.4 Finalize Installer & Set Up Nginx Reverse Proxy with Free SSL

Now run the installer to register the systemd services, configure Nginx, and request your free Let's Encrypt SSL certificate:

cd /opt/omnireborn
sudo bash deploy/install_vultr_backend.sh

# Configure Nginx for your api domain
sudo cp deploy/nginx-omnireborn-api.conf /etc/nginx/sites-available/omnireborn-api
sudo sed -i 's/api.example.com/api.yourdomain.com/g' /etc/nginx/sites-available/omnireborn-api
sudo ln -s /etc/nginx/sites-available/omnireborn-api /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# Request Free SSL Certificate from Let's Encrypt
sudo certbot --nginx -d api.yourdomain.com

Certbot will ask for an email address and to agree to Terms of Service. Type Y and press Enter. It will automatically install the SSL certificate into Nginx!

4.5 Run Deployment Health Preflight Checks

Verify that all green checks pass on your Vultr server:

# Check Streamer Collector preflight (both Robinhood 4663 and Arc 5042)
sudo -u omnireborn /opt/omnireborn/.venv/bin/python /opt/omnireborn/streamer.py --preflight

# Check API Server readiness
sudo -u omnireborn /opt/omnireborn/.venv/bin/python /opt/omnireborn/api_server.py --check
✓
Both checks should output "ok": true across all categories with "ready": true.

4.6 Start the 24/7 Background Daemons

Enable and start the background services, automated watchdogs, and daily database backup timer:

sudo systemctl enable --now omnireborn.service omnireborn-api.service omnireborn-watchdog.timer omnireborn-api-watchdog.timer omnireborn-backup.timer
sudo systemctl status omnireborn omnireborn-api
